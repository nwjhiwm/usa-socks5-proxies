## SOCKS5 vs HTTP Proxies: Why This Choice Actually Matters

You'll see most providers default-list HTTP/HTTPS proxies and treat SOCKS5 as a footnote. That ordering is misleading.

SOCKS5 sits one layer lower. It doesn't read or rewrite HTTP headers, which means:

- It works for any TCP application (and UDP through SOCKS5h), not only browsers.
- It doesn't reveal that a proxy is in use through HTTP-specific headers like `X-Forwarded-For` or `Via`.
- It handles authentication via username/password directly, no extra plugin required.

For most US-targeted tasks where you want low signature and broad compatibility, SOCKS5 is the protocol you want.
